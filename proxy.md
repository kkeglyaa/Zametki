# прокси 
install squid, открываем файл `sudo nano /etc/squid/squid.conf`, найти блок с http_access там по умолчанию стоит `http_access deny all` надо найти строку `acl localnet src` и добавить перед запретом строку `http_access allow localnet` и перезапустить `sudo systemctl restart squid`

## айкап 
открываем `/etc/squid/squid.conf` добавляем в конец файла 

`icap_enable on`
`icap_service service_req reqmod_precache bypass=1 icap://<IP-адрес-IWTM-Web>:1344/request`
`adaptation_access service_req allow all`
`icap_send_client_ip on`
`icap_send_client_username on`

после добавления перезапускаем `sudo systemctl restart squid`

### перехват https 
создаем каталог для сертификатов 

`sudo mkdir /etc/squid/ssl_cert`
`sudo chown -R squid:squid /etc/squid/ssl_cert/` 

генерим корневой серт для скюида 

`sudo openssl req -new -newkey rsa:2048 -days 720 -nodes -x509 -keyout /etc/squid/ssl_cert/Iw.pem -out /etc/squid/ssl_cert/Iw.pem`
на все вопросы ентер нажимаем

# squid.conf для ссл бамп 
находим строку `http_port 3128` и комментриуем ее
вместо не добавляем 

`http_port 3128 ssl-bump generate-host-certificates=on dynamic_cert_mem_cache_size=4MB cert=/etc/squid/ssl_cert/Iw.pem`
`sslproxy_flags DONT_VERIFY_PEER`
`sslproxy_cert_error allow all`
`always_direct allow all`
`ssl_bump client-first all`
`ssl_bump server-first all`
`ssl_bump none all`
`sslcrtd_program /usr/lib/squid/security_file_certgen -s /var/lib/ssl_db -M 4MB`

(Путь к ssl_crtd_program может отличаться в зависимости от версии Squid в Astra — проверьте наличие файла security_file_certgen или ssl_crtd в /usr/lib/squid/)

# инициализируем бд сертификатов 
`sudo /usr/lib/squid/security_file_certgen -c -s /var/lib/ssl_db -M 4MB`
`sudo chown -R squid:squid(officer вместо скюид) /var/lib/ssl_db`  
перезапускаем так же 
смотрим логи чтобы убедится что все равботает `sudo tail -f /var/log/squid/access.log`

# ПРО ИНДЕКСАТОР ПРЕДОСТЕРЕЖЕНИЯ 
(
1. Критически важная конфигурация: подключение к базе данных
Индексатору необходимо подключиться к вашей существующей базе данных IWTM-DB (PostgreSQL) для чтения и записи индексов. При установке мастер предложит вам ввести IP-адрес базы данных и имя базы данных. Если вы укажете неверный IP-адрес, база данных еще не будет готова или сеть между ними не будет доступна, установка может завершиться, но Индексатор не сможет нормально запуститься, и консоль будет продолжать показывать красный статус.

2. Легко упускаемая конфигурация: кластер Consul
InfoWatch использует Consul для управления конфигурацией и обнаружения сервисов. При установке Индексатора вам нужно указать режим работы Consul и адрес сетевого интерфейса. Внимание: в одном кластере должно быть нечетное количество серверов Consul (например, 1, 3, 5), и не более 5. Если вы неправильно настроите это, это повлияет на взаимодействие между компонентами. Если у вас всего один сервер Индексатора, обычно достаточно выбрать режим по умолчанию (или оставить поле "retryjoin servers" пустым).

3. "Скрытая" проверка: зависимости пакетов и репозитории
Как и при установке Web, вам нужно настроить локальный репозиторий (local repository) Astra Linux (обычно используется компакт-диск с ISO-образом) и отключить внешние репозитории, чтобы избежать сбоя установки из-за конфликтов версий пакетов или сетевых проблем. Если репозиторий настроен неправильно, установщик может выдать ошибку, сообщающую о невозможности найти зависимости.

4. Самая раздражающая ситуация: "установка прошла успешно, но не работает"
После завершения установки Индексатор должен прочитать конфигурацию из базы данных. Если база данных работает медленно или сетевое соединение нестабильно, в логах (/opt/iw/tm5/log/cas.log и т.д.) могут появляться ошибки, похожие на "не удается открыть файл конфигурации" или "не удается подключиться к базе данных". Обычно системе нужно некоторое время (иногда несколько минут), чтобы завершить загрузку конфигурации. Если вы видите, что статус в консоли не становится зеленым, не паникуйте сразу — возможно, она просто еще загружается. Но если через длительное время все еще есть ошибки, нужно проверить сетевое соединение между Индексатором и базой данных.

5. Ограничение "единственного экземпляра"
В документации InfoWatch особо подчеркивается, что в одном кластере процессы iw_indexer и iw_is (оба являются основными процессами Индексатора) могут быть запущены только в единственном экземпляре. Это означает, что если вы по ошибке установите второй Индексатор, это приведет к несогласованности данных. Поэтому просто убедитесь, что вы устанавливаете его только на одной виртуальной машине.Перед запуском установки сделайте ping до IP базы данных и убедитесь, что репозитории работают. Тогда всё пройдет гладко)
